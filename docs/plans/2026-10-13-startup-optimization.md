# Transformer Explainer 启动优化实施计划

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 减少启动时的重复警告，缩短本地 GPT-2 加载等待，并使加载失败、缓存不可用和开发热更新时的行为可靠。

**Architecture:** 保留现有 GPT-2、63 个模型分片、浏览器推理与教学输出。将模型加载集中到可复用的加载模块，减少中间数据复制，允许缓存失败时继续从本地服务读取；界面分别表达示例可用、模型加载和真实推理就绪。先做小范围修复与性能对照，再决定是否采用更复杂的加载方案。

**Tech Stack:** Svelte 5、SvelteKit、Vite 6.4.4、ONNX Runtime Web 1.23.0、Transformers.js、Node.js 自带测试框架。

---

## 范围与执行边界

- 2026-10-13 已完成首轮实现与类型清理，按用户要求收尾。实测、验证边界和未执行项见 [startup-baseline.md](../startup-baseline.md)。
- 保留纯本地运行、中文默认语言与英文切换、5 个示例、12 个 Transformer 块及中间计算可视化。
- 首轮不替换模型、不量化、不升级整套框架，不启用远程资源回退。中间张量是教学功能依赖，不能为了加速随意删掉。
- 当前目录没有 `.git`。实施前备份将要修改的源文件与配置；不自动初始化仓库，不执行提交或创建工作树。后续若恢复 Git，再采用小批提交。
- 保留用户自己启动的 5173 服务。测试优先使用单独端口；结束时只停止本次创建的服务。

## 已验证的基线

2026-10-13 在 Codex 内置浏览器中测量，开发服务器已经启动。每种缓存状态仅测了一次，不能当作稳定的平均值，也不代表 Safari 首次冷启动。

| 阶段                     | 无模型缓存 | 有模型缓存 |
| ------------------------ | ---------: | ---------: |
| 导航开始至分词器完成     |    2.35 秒 |    1.96 秒 |
| 模型分片读取与合并       |    4.31 秒 |    0.95 秒 |
| 合并完成至模型初始化完成 |    2.61 秒 |    3.04 秒 |
| 导航开始至模型会话就绪   |    9.27 秒 |    5.95 秒 |

- 模型实测大小：656,662,664 字节，约 626.24 MiB；共 63 个分片。
- 启动前本地资源准备脚本实测约 0.10 秒，不是首要优化对象。
- 当前完整检查：501 个类型错误、85 个警告。实施前需重新记录，避免将旧问题误判为新回归。
- 配置为每个 SCSS 文件注入 `@import`，导致 Sass 弃用警告重复出现。
- 已复现热更新卸载期间的两类真实异常：Embedding 清理事件时查不到元素；BlockTransition 的 ResizeObserver 仍访问已移除元素。
- 缓存写入的 Promise 未被处理；这是代码检查发现的可靠性缺口，尚未复现配额耗尽场景。
- 开发模式图标入口预打包文件约 5.1 MiB，是首屏优化候选；其实际耗时占比尚未测量。

## 路线选择

| 路线                                   | 收益                                   | 代价                               | 决策               |
| -------------------------------------- | -------------------------------------- | ---------------------------------- | ------------------ |
| 分阶段修复，减少模型复制，保留现有模型 | 同时改善稳定性和加载开销，便于逐步验证 | 每阶段需要真实浏览器对照           | 推荐               |
| 只清理警告，日常使用构建后的预览       | 终端更清楚，避开开发模式编译           | 模型读取与初始化仍存在             | 可作为短期使用方式 |
| 改用小模型、量化、GPU 或独立后台服务   | 可能获得更大提速                       | 可能改变教学数值、兼容性和部署方式 | 首轮不采用         |

## 任务 2：修复组件卸载和热更新异常

**Files:**

- 修改：[Embedding.svelte](../../src/components/Embedding.svelte#L74)。
- 修改：[BlockTransition.svelte](../../src/components/BlockTransition.svelte#L68)。

**Steps:**

1. 先复现热更新时的 `removeEventListener` 与 `getBoundingClientRect` 空对象错误，保留错误栈。
2. Embedding 挂载时保存监听对象，卸载时从同一个对象移除监听，不在卸载时重新查询 DOM：

   ```ts
   onMount(() => {
     const mainSection = document.querySelector('.main-section');
     mainSection?.addEventListener('click', handleOutsideClick);
     return () => mainSection?.removeEventListener('click', handleOutsideClick);
   });
   ```

3. BlockTransition 在测量前验证相关元素存在；卸载时调用 `resizeObserver.disconnect()`。将当前 `blockIdxTemp.subscribe()` 纳入组件生命周期并调用其退订函数，避免重复订阅。
4. 对该组件启动的延时动画建立清理机制，取消卸载后仍可能访问元素的回调。
5. 再次热更新，并检查块切换、展开/收起、窗口缩放和连续生成。

**Acceptance:** 连续 3 次热更新无上述异常；动画、块切换和点击行为保持一致。必须检查浏览器真实卸载流程，不能只用源码字符串断言代替。

## 任务 3：减少模型加载的中间复制

**Files:**

- 新建：[modelLoader.js](../../src/utils/modelLoader.js)。
- 修改：[+page.svelte](../../src/routes/+page.svelte#L79)。
- 修改：[fetchChunks.js](../../src/utils/fetchChunks.js)。
- 新建：[model-loading.test.mjs](../../tests/model-loading.test.mjs)。

**Steps:**

1. 先增加小规模分片测试：响应乱序时合并字节顺序仍正确；分片缺失必须失败；不得把未完成的模型标为就绪。
2. 首先只移除 Blob 和对象 URL 中转，使用安装版本已支持的 Uint8Array 输入：

   ```ts
   const session = await ort.InferenceSession.create(new Uint8Array(mergedArray), {
     executionProviders: ['wasm']
   });
   ```

   这减少一段数据中转，但 ONNX 自身仍需要把模型复制到 WASM 内存，不能承诺零复制。

3. 将初始化集中到加载模块，按模型版本和本地路径复用同一个进行中的 Promise；失败后允许重试。浏览器模块状态不得变成服务端跨用户共享的模型会话。
4. 明确会话所有权：页面卸载后不再更新其界面；已创建但没有使用者的会话应释放。热更新时不要遗留多份大模型。会话存活与页面导航策略要一致。
5. 运行真实 ONNX 推理并比较任务 1 的输出名称、尺寸、关键数值与生成流程。
6. 测量直接输入方案的耗时和可观测的内存峰值；若浏览器无法可靠测量内存，记录限制，不用模型大小推算冒充实测峰值。
7. 只有峰值或加载时间仍不理想时，再比较 4、8 与原有 63 路读取并发。并发较低不一定更快；单纯限流也不一定减少最终保留的全部分片内存。
8. 若需要进一步控制峰值，再独立设计按顺序写入预分配模型缓冲区的方案，包含分片尺寸/偏移校验。它是条件任务，不与首个直接输入修复混成一大批变更。

**Acceptance:** 字节顺序与实际模型输出正确，冷加载和缓存加载均可用，无额外会话泄漏。以同环境 3 次以上的中位数比较；目标争取至少 20% 提升，属于优化目标，不是收益承诺。若更复杂的方案没有稳定收益，不纳入默认实现。

## 任务 4：让缓存失败和加载状态可恢复

**Files:**

- 修改：[fetchChunks.js](../../src/utils/fetchChunks.js#L4)、[modelLoader.js](../../src/utils/modelLoader.js)。
- 修改：[store/index.ts](../../src/store/index.ts#L25)、[InputForm.svelte](../../src/components/InputForm.svelte#L131)、[+page.svelte](../../src/routes/+page.svelte)。
- 修改：[en.ts](../../src/i18n/en.ts)、[zh.ts](../../src/i18n/zh.ts)。
- 扩充：[model-loading.test.mjs](../../tests/model-loading.test.mjs)。

**Steps:**

1. 先写回归用例：Cache API 不可用、缓存打开失败、写入配额不足、部分缓存命中、分片 404、初始化失败、重试成功。
2. 将浏览器缓存作为可选加速层。缓存读取异常时改从本地 HTTP 服务读取；缓存写入失败不阻止本次模型使用。
3. 处理所有 `cache.put()` 拒绝，避免未处理的 Promise。记录失败原因但限制重复日志；缓存未写完不能被报告为完整缓存命中。
4. 用命中数量表示缓存状态，修复当前“任意一个分片命中便算有缓存”的统计歧义。
5. 保留本应用旧缓存清理边界，不删除其他应用的缓存；不得在异常时转到外部资源地址。
6. 使用明确状态：`tokenizer-loading`、`model-loading`、`initializing`、`ready`、`error`。模型失败时解除持续转圈状态，但仍禁止使用尚未就绪的真实模型；保留示例与重试入口。
7. 用户看到“读取模型 32/63”“初始化中”等可理解的信息。读取进度只表示读取阶段，不能把 63/63 写成整个启动完成。
8. 继续先呈现示例；模型未就绪时不得把自定义输入的缓存示例结果冒充真实推理。重试成功后恢复输入与生成。

**Acceptance:** 缓存禁用仍可本地加载；缓存写入失败没有未处理异常；失败可重试；中文与英文词典测试通过；初始化前后按钮状态正确。

## 执行顺序与停止条件

建议顺序：**任务 1 → 2 → 3 → 4 → 5 → 6**。每个任务完成后先验证，再进入下一项。

任务 2 先解决已复现的真实异常；任务 3–4 处理加载成本与失败恢复；任务 5 解决刷屏和首屏依赖；任务 6 的完整类型治理是较大的后续工作，不应阻塞已验证的小范围修复交付。

任何阶段出现教学输出变化、连续生成失败、运行时外部请求、未释放的重复会话，暂停该阶段并恢复其改动，先定位原因。复杂优化没有稳定收益时保留简单方案。

首轮产出：可运行的优化版本、前后测量记录、缓存/失败回归测试、启动与热更新验证结果、剩余类型诊断清单。不会以“警告变少”代替“速度更快”的证据。
