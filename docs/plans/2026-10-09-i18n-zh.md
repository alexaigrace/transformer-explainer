# 前端中文化实现记录（中英双语 + 切换滑块）

**目标：** 在保留原版英文的前提下，把前端界面翻译成浅白的中文，并在页面上提供中英切换滑块。

**实现方式：** 自建轻量 i18n（不引入第三方依赖），Svelte store + 词典，界面标签统一走 `$t('key')`；长文章（Article）与教科书正文用「双分支 / HTML 词典」承载，避免句子被链接和加粗切碎。

## 结构

| 文件                            | 作用                                                                 |
| ------------------------------- | -------------------------------------------------------------------- |
| `src/i18n/en.ts`                | 英文词典（原版文案，作为键的契约）                                   |
| `src/i18n/zh.ts`                | 中文词典（键与英文一一对应，`Record<MessageKey, string>` 约束）       |
| `src/i18n/index.ts`             | `locale` store、`t` 派生 store、`setLocale/toggleLocale/initLocale`  |
| `src/components/LanguageToggle.svelte` | 滑块式切换控件（中文 / EN），位于顶栏符号区                    |
| `src/components/article/Article.svelte` | `{#if $locale === 'zh'}` 中文分支 + `{:else}` 原版英文分支   |
| `src/utils/textbookPages.ts`    | 页面改用 `titleKey` / `contentKey` 指向词典，正文由 `{@html $t(...)}` 渲染 |
| `tests/i18n.test.mjs`           | 键一致性、占位符、HTML 标签、`$t()` 使用点、教科书键的静态检查         |

## 关键决定

- **默认语言为中文**，用户选择写入 `localStorage`（键名 `transformer-explainer-locale`），`+layout.svelte` 在 `onMount` 里恢复，避免 SSR 预渲染与本地存储不一致造成的闪烁。
- **保留英文原文**：`en.ts` 保存全部英文文案；Article 组件的英文分支与改动前逐字一致。
- **浅白风格**：术语保留但补一句人话解释（如 `嵌入（把文字变成数字）`、`原始分数（logit）`、`自注意力`），句式为短句。
- **模型输入不翻译**：示例句子（`Data visualization empowers users to` 等）是喂给 GPT-2 的英文提示词，保持原样。
- 切换语言时同步更新 `<html lang>`、`document.title` 与 `<meta name="description">`。

## 验证

- `npm run build`：通过（Svelte 编译覆盖全部组件与中英双分支）。
- `node --test tests/i18n.test.mjs`：通过（155 个键在英/中词典中一一对应；所有 `$t()` 使用点、教科书 `titleKey/contentKey` 都能在两侧词典中解析；`textbook.*.content` 的 HTML 标签集合一致）。
- `npm test`：本地 tokenizer 回归 + i18n 静态检查。
- 浏览器验证边界：静态检查与构建通过不代表真实浏览器内的交互已经验证；本轮以本地预览页面实际点击切换、检查中英文渲染为准（见交接说明）。

## 已知限制

- `svelte-check` 在本仓库有大量历史类型错误（原版约 498 条），本次改动不改变该基线；Article 中 `<img align>`、`<Katex style>` 的报错来自原版写法，双分支后条数翻倍但非新增类型问题。
